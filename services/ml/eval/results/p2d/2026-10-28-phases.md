# Prototype 2d — drums, Phase 3 candidates (2026-10-28)

Every candidate measured in step 25's Phase 3, losers included. The before/after report is
`2026-10-28-phase3.md` (chains `baseline`, `shipped`, `yourmt3`). Tables come from
`eval/p2d_tune.py`, which runs the shipped network once per item, input and input gain, then
re-runs the shipped peak picking offline. Scores are item-mean onset F1 at ±50 ms on the
`chosen` input (the BS-Roformer-SW drum stem) unless a table says otherwise. Split: 21 `fit` / 21
held-out `test` items; RBMA13 is not built (6 items), so `real-electronic` is empty.

## Shipped

`config/notes.personal.yaml` `instruments.drums.params`:
- `input_rms_db: -17`: the drum stem is brought to −17 dBFS RMS before ADTOF's front end;
- `thresholds: [0.08, 0.08, 0.42, 0.18, 0.32]` (BD SD TT HH CY);
- `confidence: margin`, with the isotonic table
  `config/calibration/adtof-frame-rnn@adtofAll_0-pt-85c192e.drums.json`.

- On the mixture fallback (no stem), the all-item mean goes from 0.772 to 0.798.

## Solo bypass

On the 4 solo-drum excerpts the stem, the mixture and the clean track give identical hits, so a
`solo_check` bypass would gain no accuracy. It would only save a separation. A drums analysis runs
that separation anyway for the mixer's stems, so no bypass was added.

| per-class logistic on margin | — | 0.798 | 0.029 | 0.034 | 0.83 / 0.902 | 0.13 / 0.539 | 0.03 / 0.485 |

- Held-out AUROC of the margin per class: kick 0.877, snare 0.827, hi-hat 0.759, toms 0.965 (22 hits), cymbals 0.612.
- Per-class ECE stays high for toms (0.18) and cymbals (0.21): their precision is lower than the shared table assumes.
  - The per-class logistic only trims that to 0.17 / 0.16 and adds 10 config values, so it was not shipped.
  - Toms and cymbals are always 5-class guesses, flagged `approximate`, so the drum grid already draws them with the unsure encoding.
- Shipped table: 22 knots fitted on 4,832 fit-split hits; held-out ECE 0.295 → 0.021 on 3,934 hits.

## Not measured

- **Kit split (MDX23C DrumSep → crash/ride, open/closed hi-hat, tom lines).**
  - The checkpoint is downloaded (`mdx23c-drumsep` register record, 438 MB) and `p2d_tune.py kitsep` / `kit` are written.
  - Loading the checkpoint was blocked by this PC's safety rule for code from external sources, so it waits for the owner.
  - Until then every hi-hat, tom and cymbal choice stays a flagged 5-class default. Baseline kit-piece accuracy (`2026-10-28-phase3.md`): hi-hat open/closed 0.77–0.92, crash/ride 0.30 (MDB) to 0.97, tom line 0.00–0.38.
- **ADT_STR:** not run. It needs its own model code (an autoregressive encoder-decoder, not in `transformers`), which the same rule blocks, and it was trained on synthesized drums only.
- **Velocity:** ADTOF has no velocity output. `velocity` stays empty.
- **Fine-tuning:** not proposed now.
  - The tags that stay weakest are brushes (0.66), swing (0.65) and phone (0.68) on 2–6 items each.
  - Groove/E-GMD renders could cover brushes and swing. Expected gain is unknown at this test-set size, and the electronic tag is already 0.93.
  - The owner decides at stop point 3 whether to spend the CUDA hours.
