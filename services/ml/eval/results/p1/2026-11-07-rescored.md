# Prototype 1: rescored and reselected (step 28, 2026-11-07)

Why: the step 07 numbers (`2026-10-21-overlap.md`) counted silent references in uSDR medians
(3 of 20 clips: `mu-too-bright` and `speak-softly-broken-man` bass, `skelpolu-resurrection`
vocals are digital zero in their windows) and picked the guitar/piano windows by BS-Roformer-SW's
own stem energy. This report re-runs every model in the map on the PC (RTX 3060, CUDA, 129 W cap)
through the shipped wrapper and scores with the corrected rules.

Metrics (`splitune_eval.scoring.SEPARATION_VARIANT`): uSDR (MSST/MDX whole-clip ratio); SI-SDR,
bleedless and fullness ported from MSST `utils/metrics.py` @84b1eac (`splitune_eval.msst`, identical
to upstream on a shared fixture); cSDR = plain SDR on 1 s frames, median, silent-reference frames
skipped (self-contained; mir_eval's deprecated BSS Eval v3 and museval are no longer used); SI-SAR
(Le Roux 2019, every MUSDB stem as the interference basis). A reference below -40 dB vs the mixture
or -60 dBFS RMS is **silent**: left out of these and scored as **leakage** (estimate energy vs
mixture, dB). On the 50 windows the silent references are digital zero and the quietest real one is
-22.7 dB, so the threshold has 17 dB of margin either way.

Commands:

```
uv run --no-sync python eval/sep_matrix.py run --variant aac128 --model M     # every window
uv run --no-sync python eval/p1.py select                                      # → musdb18hq-p1-v2
uv run --no-sync python eval/sep_matrix.py report --set musdb18hq-p1 ...       # v1 clips
uv run --no-sync python eval/sep_matrix.py report --set musdb18hq-p1-v2 ...    # v2 clips
```

Full tables (every metric, condition, n, mean, p10 and the worst 3 clips):
`eval/results/sep-robust/2026-11-07-v1.md` (v1 clips) and `2026-11-07.md` (v2 clips).

## 2. Unbiased selection (`musdb18hq-p1-v2`)

`p1.py select` now ranks vocals/drums/bass windows by the reference stem's energy and guitar/piano
windows by the loudest stem any candidate model gives (SW, htdemucs_6s, becruily for guitar),
among windows the tagger hears, ties by clip id (unit-tested for order independence). Result: the
same 12 guitar/piano windows as v1 (SW's stem was the loudest candidate in every one), one
different vocals window (`al-james-schoolboy-facination`) and one different bass window
(`the-mountaineering-club-mallory`). The v1 manifest stays as `eval/sets/musdb18hq-p1.yaml`.

Median uSDR on v2 (AAC 128): SW bass 8.80 / drums 10.89 / vocals 11.97, viperx vocals 12.19, Kim
vocals 11.71, htdemucs_ft 6.78 / 8.23 / 8.65, htdemucs_6s 5.00 / 7.58 / 8.08 dB. The order of the
models is the same as on v1 and as in step 07.

## 4. Possibly in-sample

Only htdemucs_ft documents its training data, and its released grids exclude the MUSDB18-HQ test
split. BS-Roformer-SW, viperx, Kim, becruily and htdemucs_6s's extra guitar/piano data are
undisclosed (`compliance/register/models/*.yaml`, `musdb18_test_in_training`), so their absolute
numbers on these MUSDB test windows are **possibly in-sample** and may flatter them against
htdemucs_ft. Downstream tests (P2g, P2p, P2d) on non-MUSDB sources don't share this risk.
